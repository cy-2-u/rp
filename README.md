# RP Hub 魔改版

一个 Cloudflare Pages Worker 项目：反向代理 [RP-Hub](https://github.com/STA1N156/RP-Hub)（作者的酒馆类角色扮演前端），在不修改作者代码的前提下加入**云同步、R2 聊天图片托管、图片管理**等功能。

- **免服务器运维**：部署到 Cloudflare Pages 免费版即可，数据存在自己的 R2 桶里。
- **数据自主**：聊天记录、角色卡、生成图片全部保存在自己的 Cloudflare 账号，不经过第三方。
- **不改动作者代码**：作者前端原样代理；增强能力由 Worker 注入的几个脚本和一份外部适配脚本提供，作者更新后仍可用。

维护者文档（架构设计、同步协议、测试与发布流程）见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 功能

### 云同步

- **上传到云端**：本机数据整体替换云端，云端没有数据时即首次备份。首次上传会完整扫描并建立本地缓存；之后的增量上传只读取变更日志，没变的数据按哈希跳过，通常几秒完成。
- **从云端恢复**：云端数据整体替换本机，一个进度条走完自动刷新页面。中断后再点一次即可重试，已恢复的部分不会损坏本地数据。
- **自动保存**：可设置 1～1440 分钟间隔自动上传；页面在后台时暂停计时。每次结果（成功/失败）显示在浮窗右下角的徽标上。
- **安全边界**：上传/恢复是整体替换语义，设计给单设备单人使用；跨 localStorage 和多个 IndexedDB 的恢复不是原子事务，但失败后本地数据保持可用的上一状态，重新恢复即可。

### 图片托管

- 聊天里的 AI 生成图片自动保存到自己的 R2，不再受图片站外链过期影响；换设备、清缓存后图片仍在。
- **图片管理页**：按角色分组浏览、搜索、查看原图、批量删除。
- **固定生图**：每条消息的生图参数按槽位持久化，刷新页面、切换画风后旧图仍能原样重放，reroll 才会重新生成。
- **生图门控**：跟随作者的"自动生图"世界书开关；关闭后新消息不再生图，已有图片照常显示。
- **YNAI 中转**：生图密钥以 `YNAI-` 开头时自动走第三方中转（模型列表可选），普通密钥走原生通道；两者缓存共享，历史图片键稳定。

## 部署

### 前置要求

- 一个 Cloudflare 账号（免费版即可）。

### 一键部署（推荐）

1. 打开部署页（本仓库 GitHub Pages，见 docs/ 目录截图教程）。
2. 填入 Cloudflare API 令牌，点击部署：自动创建 R2 桶、上传站点并创建 Pages 项目。
3. 部署完成后在 Pages 项目里确认 `RP_SYNC_R2` 绑定存在。

### 手动部署

1. 创建一个 R2 桶。
2. 创建 Pages 项目，构建输出目录设为 `page`，构建命令留空。
3. 把 [`page/`](page/) 目录的四个文件上传（或推送到仓库让 Pages 自动构建）。
4. 在项目设置里绑定 R2 桶为 `RP_SYNC_R2`。

### 访问密码（可选）

设置环境变量 `RP_SYNC_PASSWORD` 后，站点打开时先显示验证锁页：输一次密码即可，之后同步与图片管理共用。不设置则免密开放——**公网部署建议设置**，否则任何知道网址的人都能读写你的云端存档。

### 在线更新

部署页提供"更新"按钮：输入令牌后列出账号下的本项目部署，一键刷新为仓库 `page/` 最新版（不改密码、不动数据）。更新后刷新页面即生效。

## 部署后自检

1. 首页出现"同步"和"图片管理"，设置中出现"固定生图"。
2. 上传少量数据，在另一个浏览器（或隐身窗口）恢复一次，数据一致。
3. 生成一张图片，刷新页面后图片仍显示。

遇到问题见 [DEVELOPMENT.md](DEVELOPMENT.md) 的"部署后自检与排障"章节（401/409/503 等错误对照表）。

## 技术概览

- 同步协议 `rp-sync-paged-jsonl-v4`（schema 13）：数据切块为内容寻址分片（1MiB/512 条），清单分页验证，按快照校验码断点续传，根清单以 ETag CAS 切换版本；针对 Cloudflare 免费版的 CPU/子请求/连接数限制设计。
- 部署形态：单个 `_worker.js`（Pages Worker，无构建步骤），四个前端脚本随页面注入，一份外部适配脚本从固定 Raw URL 在线读取（适配作者页面更新）。
- 测试：11 个离线套件覆盖协议、恢复、运行时与性能预算（300MB 规模模拟），发布前本地全量回归。
