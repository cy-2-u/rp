RP Hub 魔改版：当前实现与维护约定
更新时间：2026-09-17

一、运行结构

Worker 代理作者在线网页及其资源，本地不保存整份作者前端。
项目仓库 github.com/cy-2-u/rp 即项目本体：代码、测试和说明文档都在仓库里，clone 即开发目录，改完 commit + push。
作者网页：https://sta1n156.github.io/RP-Hub/
作者页面负责角色、聊天、记忆、预设和正文渲染；魔改扩展负责云同步、聊天图片托管/固定/重绘和少量 UI。
作者源码参考：仓库同级放一份 RP-Hub-main（或用 RPHUB_UPSTREAM_DIR 指定）；runtime-smoke 按环境变量 → 仓库同级 → 本机旧路径的顺序查找。

文件职责：
- _worker.js：作者资源代理与源码替换、R2 图片接口/图库、同步 API；保持单文件 Worker。
- magic-extension.js：图片请求共享、槽位记录保存、图片显示绑定、魔改 UI 入口及下滑按钮。
- DB/bootstrap.js：同步缓存、分桶构包、受界限的上传、独立页面拉取恢复和同步面板；文件头部按字节内联了有界上传引擎与防抖保存桥（原 upload-engine.js / persistence-bridge.js 已并入并删除）。
- adapter/rp-hub.json：适配清单正本（文件名与 id 固定，不含日期）；生产环境 Worker 硬编码的 GitHub Raw 地址拉取的就是仓库里这份文件，不随 Pages 资源打包。
- DB/dirty-tracker.js：记录本地变动，并协调跨标签页恢复期间的写入暂停。
- DB/styles.css：同步面板样式。

二、部署配置

R2 绑定：RP_SYNC_R2。
可选同步/图库密码：RP_SYNC_PASSWORD。不配置时沿用无密码访问。
适配清单地址已硬编码进 Worker：https://raw.githubusercontent.com/cy-2-u/rp/main/adapter/rp-hub.json；部署不需要设置任何清单变量。RPHUB_ADAPTER_URL 仅保留为本地测试的 file:// 覆盖入口。
Worker 不内置适配规则，只缓存外部清单 30 秒；清单仅维护者本人更新，不设防篡改校验（RPHUB_ADAPTER_SHA256 死代码已删除）。
ASSETS 由 Pages 提供，部署时需要包含本地 DB 资源及 magic-extension.js；本地资源命中直出，未命中的全部路径（含作者未来新增页面）一律回源作者站点，不再维护代理路径清单。
作者网页插入和源码替换规则由外部适配清单提供；GET /__rphub/adapter.json 返回当前 UI 配置摘要。
Worker 对已经按适配清单改写过的 app.js 按适配对象和上游 etag 缓存结果；上游返回 304 时直接复用改写正文，避免重复下载和替换。
本地测试：在 .sync-tests 目录执行 `npm test`（runtime-smoke 冒烟检查 + restore-sim 全流程同步模拟，使用 fake-indexeddb 与内存 R2）；也可先设置 `RPHUB_ADAPTER_URL=file:///D:/路径/adapter.json` 验证另一份本地清单。

三、图片

1. 正式图片协议沿用魔改版1：
   /api/rp-image 参数请求；R2 key 为角色名称目录加参数 checksum。
   checksum 保留 provider、nocache、reroll_nonce 的身份含义。
   历史 provider 字段用于读取旧对象，不代表开启第三方生图。

2. 图片生成仍使用标准上游；Worker 等 R2 写入成功后返回。
   图片节点使用不含 token/generate 的 R2 读取 URL，不使用上游临时 URL。
   首次生成和主动重新生成会提交生图请求；普通读取失败后的“重新加载”不调用生图。

3. 任务职责分离：
   - 网络请求按读取 URL 共享；
   - 每个角色/消息/图片槽位独立提交固定记录；
   - DOM 只绑定槽位任务及显示状态。
   不同图片保持并发，不新增生图并发限制。
   DOM 重建不重复生成，也不会让失效的旧绑定覆盖新任务。

4. 固定记录保存在：
   RPHubDB / store / rp_hub_image_renders_<角色UUID>
   继续使用 messageId、messageIndex、contentHash、occurrenceIndex、prompt、promptHash、paramsSnapshot。
   不新增另一套记录格式或图片迁移系统。
   写入失败保留待保存状态并提示；同步前补存，仍失败就停止上传。
   关闭固定只影响后续记录持久化，已固定图片继续读取原记录。

5. 图片读取失败与生图失败区分显示。
   “重新加载”只重读 R2；“重新生成”继续采用作者重绘交互及魔改请求。
   重绘成功后提交新固定记录；失败不替换已保存的旧记录。

6. 图库删除维持两阶段，并受子请求预算约束：
   前端先隐藏（乐观更新，清空分组后该组立即从页面消失），
   清空分组请求只发角色名，由 Worker 按当前 R2 目录状态展开（页面加载后新生成的图也会被删），
   前端按每批 20 张循环提交（与服务端单次预算一致，测试断言两个常量耦合）；
   Worker 单次最多处理 20 个目标（每角色目录一次 list 判存在性，不逐 key head），
   超出部分以 remainingKeys 返回由前端续传；删除标记逐个写完后才返回，
   原图/缩略图用 R2 批量 delete 后台清理（ctx.waitUntil）。
   部分失败只保留成功删除的部分，失败项恢复显示；分批中途抛错时先恢复删除前快照再剔除已接受项。
   进入/刷新图库时扫描和对账（墓碑过滤 + 批量清理陈旧对象），缩略图补全为 3 路并发。

7. 图库返回按钮在标题左侧，刷新/选择在右侧。
   选择模式显示已选数量和删除操作；多选只更新 tile，不重建全部图片。
   刷新保留搜索词、展开数量和滚动位置。

角色生成器的图片继续使用作者原有流程，不纳入聊天图片托管。

四、同步

1. 远端协议：
   rp-sync-bounded-jsonl-v3，schema 12；
   rp-sync/main/manifest.json；
   rp-sync/main/packs/<sha256>.bin。
   上传将已判定需要更新的分片每 8 个或 4MiB 合并为一次 HTTP 请求，客户端默认只保留 1 个批次在途；下载并发为 10。
   Worker 以流式读取批次正文，单批最多 8 个分片、4MiB，最多 3 个 R2 写入并发；各分片仍保存为独立的内容寻址 R2 对象。
   schema 12 迁移是维护者批准的一次性清理：检测到 `rp-sync/main/migration-v12.done` 缺失时，上传流程先按 R2 分页
   批量删除 `rp-sync/main/` 下的旧清单、分片和旧标记，删除完成后才写入新标记；中断可从游标续跑。
   清理只作用于 `rp-sync/main/` 命名空间，`rp-images/` 图片对象和其他前缀一律保留。
   已完成迁移的桶重复 reset-upload 直接返回；schema 11 请求被拒绝。恢复页在未迁移的桶上明确提示先执行一次上传，不显示“暂无云端数据”。
   Worker 对同步 manifest 按 etag 做 isolate 内缓存（上限 30 秒）：每次调用先用 R2 head 校验 etag，命中才复用缓存，pull-pack 逐分片下载不再重新解析整份清单。
   清单不存在、JSON 损坏或校验不过时 Worker 返回错误并停止读写，不再把坏清单当作“云端无数据”覆盖。

2. 不修改作者本地角色和聊天存储格式。
   主页面上传前只清空已经存在的待保存任务，不每次无条件调用作者全量 saveData。
   固定图片写入与已开始的 IndexedDB 写入也必须完成。

3. 本地变更日志与稳定分桶：
   小对象分桶合并，大数组按 128 项分页；每包最多 256 项，目标约 512KB。
   业务写入与变更日志在同一 IndexedDB 事务内提交或回滚：dirty-tracker 在已知库上加内部 `__rp_sync_journal_v2` 存储，
   put/add/delete（含 IDBKeyRange 范围删除，先 getAllKeys 记录实际键）、clear、cursor.update/delete 全部记日志；
   自增键在写成功后用 request.result 记录实际键；日志写入失败会中止业务事务，不再吞异常。
   作者代码 open(name, 1) 由 open 门面转为按当前版本打开，日志升级不会引发 VersionError；跨标签页 versionchange 自动关闭旧连接。
   localStorage 每次业务写入前先写入 `rp_sync_intent_v2:<uuid>` 意图键（各写各的，跨标签页互不覆盖），上传确认时删除对应意图键；
   写入相同值不再产生意图；日志存储键与恢复状态键不参与追踪。
   上传只按日志候选键读取业务数据：正常增量不再全库游标扫描；clear 直接清缓存条目，不扫描业务库。
   首次基线和“重建本地索引”按钮才会完整扫描；旧缓存格式、追踪 epoch 变化或日志重建时明确报错，
   需要人工点重建，不会静默全扫或覆盖云端。
   序列化使用确定性 canonical JSON（键排序、拒绝 undefined/NaN/bigint/循环引用），对象属性顺序变化不再产生假分片；
   候选记录与缓存内容逐字节比较，相同则只确认日志、不重建桶、不上传。
   首次扫描 IndexedDB 时每个事务最多读取 64 条记录，并以约 8MiB 的估算记录大小作为提前截断边界；单条超大记录仍允许单独读取。

4. 构包和上传相连：
   已构造的变化包直接比较并送入上传，不在同一次成功上传中再次构建。
   只保留在途上传及当前桶需要的字节，完成后释放；
   缓存更新中途失败时受影响桶先写入待重建列表，重试时继续，不回退全扫。
   上传前先记录日志水位（各库 journal 最后序号 + localStorage 意图键清单），云端提交成功后才确认对应范围；
   上传期间发生的新写入水位更靠后，保留到下一次上传。
   相同 checksum 的分片在一次同步中只上传一次；未变化分片仍不读取缓存字节、不上传。
   上传准备阶段会列出已经写入 R2 的内容寻址分片；上次上传中断后，下一次只补传尚未成功写入的分片。
   提交时通过 R2 分页 list 统一对照 key 和 size，不再对每个分片单独 head。
   提交带 baseVersion+baseChecksum，与浏览器已确认基线双重比对；云端与基线不同即拒绝上传，不自动合并、不用旧本地快照覆盖别端。
   除 schema 12 一次性迁移外不再有孤儿分片自动清理；删除旧分片必须由维护者显式操作。

5. 拉取在 /sync-restore 独立页面进行：
   先下载并完整校验，再暂停其他同源页面写入；
   等待共享写入锁和现有写入完成后应用远端数据。
   结束后旧页面刷新，旧内存不允许继续写入。
   恢复完成时记录云端水位并清空当时已有的本地变更日志与意图键；恢复期间的写入不追踪（写入暂停由锁保证）。
   恢复需要支持 Web Locks 的浏览器；旧版本标签页应先刷新。
   恢复失败或 401 时保留“重新恢复”按钮并弹出密码输入，不再把入口移除后无法重试。

6. 不创建本地恢复备份，不宣称跨 localStorage 和多个数据库的写入为原子事务。
   恢复窗口异常关闭后可从等待提示重新进入恢复页面。
   正式数据应用中断时需要重新拉取完成恢复。

7. 同步入口点击立即打开面板，再检查连接/密码。
   操作为“上传到云端”“从云端恢复”，状态只显示当前动作。
   出错保持当前进度并显示错误，不跳到 100%。

8. rp_hub_presets 不参与同步、恢复覆盖或清理。
   预设加载和页面内修改行为继续由作者决定。

五、其他 UI 与作者更新

固定生图入口继续位于高级设置原有位置。
同步入口在侧栏用户区域，图片管理入口在侧栏导航。
下滑按钮仍位于输入区域上方，使用底部哨兵与单个 IntersectionObserver；本轮不增加其他行为。
温度和流式选择不在刷新时强制重置。

作者更新后的检查位置：
- 外部适配清单：替换规则、源码标记和 UI 选择器；修改后无需重新打包 Worker。
- sourceChecks 运行时强制校验：Worker 在改写 app.js、注入主页面 UI 配置和 /__rphub/adapter.json 前对照真实上游文件核对 contains 标记
  （结论按适配对象缓存，不超过 30 秒窗口；页面请求只校验手头内容、其余路径延迟到 app.js 请求，避免额外下载）。
  任一标记失配即整站回退：app.js 不改写、UI 配置不下发、注入脚本自行降级，与替换规则未命中同一"全有或全无"语义。
- /__rphub/adapter.json：前端读取当前清单的 UI 摘要。
- AUTHOR_BASE：作者网页地址。
- rewriteAuthorHtml：主页面及其他页面的脚本和样式插入。
- rewriteAuthorScript：共 6 处替换，分别是流式重置、温度重置、图片记录清理、记忆设置保存、设置/角色保存与上传入口、图片任务接入。
- authorSourcePattern：将固定源码片段转换成允许空白与注释变化的匹配规则。LF/CRLF、缩进、压行和简单字符串的单双引号变化不影响匹配，不修改片段外的作者源码或字符串内容。
设置、角色和记忆设置复用同一个防抖保存队列；不再单独替换作者 debounce 函数，也不再跟踪 _memorySettingsSaveTimer。
替换前仍检查匹配数量。函数改名、作用域或实际保存/生图流程变化不属于排版变化，需要重新核对，而不能只放宽匹配。
任一替换未匹配时，整份 app.js 回退为作者原脚本，不返回适配错误脚本，也不应用半份补丁。
回退期间同步和固定生图入口不显示；图片管理和下滑按钮继续保留。作者原有生图不具备魔改固定/托管能力，恢复适配并刷新后再使用这些功能。
适配层校验分两层：本地冒烟测试在更新外部适配清单后用 file:// 地址执行 runtime-smoke，
其中 sourceChecks 健康场景用真实作者 index.html / ui-components.js 比对，作者改结构会变红；
线上 Worker 同时在运行时对照真实上游强制校验 sourceChecks，失配整站回退。
Worker 不提供 /healthy 检查端点（免费版 CPU 限额下无法承载完整校验）。只有 Worker 逻辑变化时才需要重新部署。

本轮代码检查：
- 缩略图补全使用逐项独立的循环变量，避免三路异步回调都引用最后一项。
- 清理重复的键序列化函数、无用的密钥包装函数、未读取的图片任务字段、同步下载冗余字段/响应头和未使用的同步副标题样式。
- 图库列表不再请求未使用的 R2 httpMetadata；原图响应仍正常读取 contentType。
- 图片协议、R2 图片 key、作者角色/聊天存储不变；同步升级为 schema 12，迁移一次性清理 rp-sync/main/ 并保留图片。
- 删除 RPHUB_ADAPTER_SHA256 死代码（清单仅维护者更新，无防篡改需求）。
- 图库删除按子请求预算重构：目录级 list 判存在性 + R2 批量 delete + 单次 20 目标上限与 remainingKeys 续传，前端每批 20 张与服务端预算一致。
- 行级复查（2026-09-17）：
  handleImageRender 顺序化——原图命中只花 1 次 R2 get，未命中才读墓碑（浏览热点路径 R2 读减半）；
  生图缺 token 401、缺 tag 400，不再走异常转 500 的路径，buildImageUpstreamUrl 去掉重复防御只负责拼地址；
  prepare-upload 与 pull-manifest 的重复实现合并进 handleStatus（同一功能两个函数）；
  pull-pack 的 some+find 双扫描改单次 find；上传引擎与防抖保存桥按字节合并进 bootstrap.js，
  作者页注入从 7 个节点缩到 5 个；未注册路径 catch-all 回源作者站点，删除硬编码代理路径清单；
  bootstrap 缓存比较改为与缓存字节逐位比较（不再 JSON.parse 后重序列化）、三个重试循环合并为 withSyncRetry、
  删除只写不读的 state.watermark、pull-manifest 请求带 schemaVersion 版本门控；
  图库管理页 deletePayload 修复"部分批次成功后抛错"的 UI 恢复缺陷（先回滚快照再剔除已接受项）；
  适配清单删除无代码引用的 ui.navigation.panel/openTrigger 字段；
  适配文件名与 id 去掉日期（adapter/rp-hub.json，Worker 硬编码地址同步更新），
  loadAdapter 删除全项目无调用方的 fresh 参数与 _rph_adapter cache-buster 分支，
  测试脚本 upstreamRoot 增加仓库同级 RP-Hub-main 回退（clone 后无需改路径即可跑测试）。
- magic-extension：固定生图开关改为相对"沉浸模式"锚点插入（不再依赖 children[4] 位置）；
  生成任务 Promise 结束即清理，槽位任务上限 128 条按插入顺序淘汰已结算条目，进行中任务保留。
- 同步缓存状态只持久化一份分片清单（state.packs），读回时回填 state.snapshot.packManifest，大库索引写入体积减半。

本轮验证范围：
- 作者本地源码的 LF/CRLF、缩进、空白、压行、注释和引号变体，改写后语法结构一致；缺失、重复和真实结构变更会在内部检查中判定不匹配，普通页面整份回退，本地冒烟测试报告失败。
- 本地模拟设置/角色/记忆待保存任务合并、聊天保存失败阻止上传，以及失败任务重试。
- 本地模拟相同图片请求共享生成、两个位置独立保存、刷新后切换画风/清空密钥仍读取固定图、重绘仅更新对应位置。
- 图库缩略图三路乱序完成和单项失败重试。
- 使用模拟 IndexedDB、Worker 和内存 R2 完成首次上传、增量上传与独立拉取恢复；验证预设排除。
- 图片 Worker 的首次生成、缓存读取、缺图只读和删除标记行为。生图 API 全流程通过本地模拟：
  命中恰好 1 次 R2 get（不读墓碑）；未命中 2 次（原图+墓碑）；墓碑命中返回 SVG 占位且 POST 不重新生成；
  reroll_nonce 换新签名重新生成；上游 503 透传、非图片 content-type 502、超 64MiB 413、PUT 405；
  失败请求不写 R2、不产生额外上游调用。
- catch-all 代理通过本地模拟：本地 4 个静态资源直出且上游调用为 0；作者新增页面自动回源；
  主页注入 5 个节点（css、dirty-tracker、内联配置、magic-extension、bootstrap）按序出现且不再引用已合并文件；
  非主页只注入 dirty-tracker；非 GET 保留方法；作者 404 透传；无 ASSETS 绑定时本地路径降级回源；update-check 桩不回源。
- 同步 manifest 的 etag 缓存通过本地模拟：重复 pull-manifest 和 pull-pack 不再重复读取解析清单；manifest 更新后 etag 变化立即读取新版本，缓存永不返回过期清单。
- app.js 改写缓存通过本地模拟：相同适配对象和上游 etag 下复用改写正文；仍发送条件请求，但 304 不重新下载正文或执行替换；上游 etag 变化后重新改写。
- 模拟替换点缺失、重复及图片接入点变化：普通 app.js 返回 HTTP 200 和完整作者原文，不保留部分替换；同步/固定入口在缺少保存接入时不挂载。
- 首轮 IndexedDB 扫描批量读取最多 64 条记录且约束在 8MiB 估算大小内；大记录不会被拆坏，扫描不会一次性装入全部数据库。
- 模拟 1000 个变化分片：上传请求为 125 次；1000 个全部未变时为 0 次；仅 3 个变化时为 1 次。
- 模拟 1000 个分片提交：逐包 head 为 0 次，list 为 1 次，并能识别缺失分片；2501 个 key 只调用 3 次批量删除。
- schema 12 一次性迁移通过本地模拟：1200+ 旧对象分两页清理、游标续跑、完成后才写标记；`rp-sync/main/` 之外的键全部保留；已完成迁移重复调用直接返回；schema 11 请求被拒绝。
- 同步密码 401 流程通过本地模拟：auth-status 的无密码/错密码/正确密码三态、未带或错误密码时各 JSON action 与二进制批量端点一律 401、未迁移桶返回 resetRequired、未配置密码时全部放行。
- 图库管理 API 通过本地模拟：分组列表与墓碑过滤、陈旧对象后台批量清理、登录会话 Cookie 授权、单次删除 20 目标上限与 remainingKeys 分批续传、缩略图读写与原图缺失拒绝、无密码环境直通。
- sourceChecks 强制校验通过本地模拟：健康场景用真实作者 index.html / ui-components.js 比对通过并注入 UI 配置、改写 app.js；index.html 标记失配时页面不下发配置、adapter.json 503、app.js 返回作者原文；ui-components.js 标记失配时 app.js 同样不改写。
- 图库管理页内联脚本固化为 runtime-smoke 用例：把 `_worker.js` 里的页面模板字面量按线上相同方式求值后，对每个内联脚本做 `new Function` 纯编译（不执行），
  并断言前端分批大小与服务端单次预算耦合一致——`node --check` 检查不到嵌在 HTML 里的这段手写脚本。
  本轮升级为**真实执行**模拟：DOM 桩 + 内存 R2 + 真实 Worker，1085 张大数据跑通登录流（错误密码提示、正确密码进入）、
  清空本组乐观消失后由服务端实时展开为 1+52 批、把页面加载后新增的 3 张也删掉（共 1043 墓碑、原图全部清理、他组不受影响）、
  40 张分两批且第 2 批失败时已接受 20 张保持删除、其余 20 张恢复显示、选择清空、报错文案与颜色正确。
- 批量提交成功、缺失分片识别、批量上传和中断后复用已写入分片均通过本地模拟；旧单包上传接口已拒绝且不会写入 R2。
- `restore-sim.mjs` 使用 fake-indexeddb 和内存 R2 完成“首次上传 → divergent 本地数据恢复 → 增量上传”三阶段回归，并验证大数组分包、缺失记录删除、预设排除及保留项。
- 阶段 4 严格增量回归：对象键顺序变化 0 个新分片且不触发新版本；事务中止不产生分片；cursor.update、范围删除、clear+新记录、5105 个变化键全部保留；
  后续上传对业务库 readonly 游标计数为 0（不再全扫）；上传期间新写入保留到水位之后的下一次上传；提交响应丢失后重试不重复上传分片；
  云端被别端更新后，陈旧客户端被基线比对拒绝且不产生上传请求、不覆盖云端清单。
- `_worker.js`、`magic-extension.js`、`DB/bootstrap.js`、`DB/dirty-tracker.js` 及两个同步测试脚本语法检查通过；没有访问真实用户数据、调用真实生图服务或部署。

六、本轮上传边界与平台依据

- Workers Free 当前限制按 100,000 请求/天、每次 10ms CPU、128MiB isolate 内存、每次 50 个子请求和 6 个同时出站连接设计；免费请求额度按 UTC 午夜重置。
- R2 Standard 免费额度按每月 10GB-month、100 万 Class A、1000 万 Class B 操作设计；超出额度前应先观察实际用量。
- 4MiB/批次和客户端单批次在途是本项目的保守工程边界，不是 Cloudflare 的硬性最小值；它们用于避免把本地全部文件或多个大批次同时放进浏览器/Worker 内存。
- 首次上传、人工“重建本地索引”以及 schema 12 迁移会完整读取本地数据/旧云端对象；之后的每次上传只读取日志候选键，不在上传路径全库扫描。
  本地测试不验证真实免费版 CPU 预算，批量上传 CPU 耗时仍需部署后看指标。

本清单只记录现有实现，不维护作者历次更新的功能汇总。
